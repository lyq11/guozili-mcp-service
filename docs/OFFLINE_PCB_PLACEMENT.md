# U 锚点 PCB 离线自动布局说明

## 1. 文档目的

本文定义一套基于 U 类核心器件或其他功能器件作为锚点的 PCB 离线自动布局流程。

该流程读取 `pcb_inspect` 导出的 PCB 快照，在本地 Python 程序中完成器件归类、区域内布局、区域级布局、几何检查和线长评估。程序只生成候选变更，不直接修改 PCB；只有通过安全门禁的结果，才允许交给 EasyEDA MCP 的 `pcb_transform_components` 执行。

首版目标是得到一套可解释、可复现、可检查的工程原型，而不是替代完整的商业布局器。

## 2. 设计目标

- 根据原理图页、网络关系和人工确认的功能语义，将 PCB 器件归入相应功能区域。
- 以 MCU、电源芯片、连接器、晶振、变压器、天线等关键器件作为区域锚点。
- 对去耦电容、晶振外围、接口保护等有明确电气关系的器件执行结构化近端放置。
- 在板框、孔洞、禁布区、锁定器件和器件间距约束下生成候选坐标。
- 支持连接器贴边、指定朝向、有限外伸，以及区域间最小距离要求。
- 对布局前后的估算飞线长度进行比较，拒绝明显退化的结果。
- 用独立门禁文件隔离“算法输出”和“允许实际应用的输出”。
- 在真正修改 PCB 前重新读取当前状态，防止过期结果覆盖人工修改。

## 3. 非目标与首版限制

- 不进行自动布线、铺铜、阻抗计算或电源完整性分析。
- 去耦电容朝向仅是“电源焊盘朝向目标引脚”的启发式策略，不是环路电感求解器。
- 宏观区域布局使用确定性启发式算法，不是全局优化求解器。
- 板内判定使用器件包围盒采样，不做完整的封装多边形裁剪。
- EIA 数字缩写值（例如 `104`）首版不转换为 `100nF`。
- 若快照只有器件当前旋转角度下的轴对齐包围盒，则任意角度旋转后的包围盒只能保守估算，可能产生误报碰撞。精确计算需要封装 courtyard 或封装图元数据。
- 首版只支持一个外部板框及其内部孔洞。发现多个互不包含的外部闭环、嵌套实体岛或无法闭合的轮廓时，程序必须报告“不支持/板框异常”，不得猜测轮廓语义。
- 若首版未实现顶层和底层分侧碰撞检测，应明确以单面布局模式运行；不得把双面可重叠器件误报为同面碰撞后静默调整。

## 4. 总体流程

```text
pcb_inspect 快照
        │
        ├─[0] anchors.py
        │       └─ anchors.template.json
        │              └─ AI/人工确认 → anchors.json
        │
        ├─[A] regions.py
        │       ├─ regions.json
        │       └─ region-params.template.json
        │              └─ AI/人工补充语义 → region-params.json
        │
        ├─[C] place.py
        │       ├─ changes.json
        │       └─ report.json
        │
        ├─[Gate] apply_gate.py
        │       └─ validated-changes.json（仅检查全部通过时生成）
        │
        ├─重新调用 pcb_inspect，校验源状态未变化
        │
        └─调用 pcb_transform_components 应用变更
```

各阶段必须采用文件输入/输出，保证中间结果可审查、可复现，且不依赖 EasyEDA 运行时执行算法。

## 5. 输入数据

### 5.1 PCB 快照

输入为 `pcb_inspect` 的原始 JSON，至少包含：

- PCB UUID。
- 器件 ID、位号、Value、坐标、旋转角度、锁定状态和所在面。
- 器件包围盒和焊盘绝对坐标。
- 焊盘网络。
- 板框直线和圆弧图元。
- 禁布区等区域图元。
- 铺铜网络信息。
- 原理图页归属；优先使用 `pcb_inspect` 中器件的 `schematicPage` 字段，必要时允许额外输入原理图器件清单作为兼容来源。

### 5.2 快照哈希

`sourceSnapshotHash` 使用 SHA-256 计算。哈希输入必须是规范化后的相关快照内容：

- JSON 对象键按固定顺序序列化。
- 数组中无语义顺序的实体按稳定 ID 排序。
- 数值采用统一表示。
- 不包含仅影响展示、时间戳或字段顺序的内容。

哈希用于审计和快速识别来源，但不能代替应用前的逐器件状态核验。

## 6. 阶段 0：锚点提议与确认

`tools/pcb-layout/anchors.py` 根据可配置的位号前缀映射提议锚点：

| 位号前缀 | 默认角色 |
|---|---|
| `U` | IC |
| `J` | connector |
| `Y`、`X` | crystal |
| `ANT` | antenna |
| `T` | transformer |
| 大封装 `L` | 待人工确认 |

程序生成 `anchors.template.json`。AI 或人工必须执行以下确认：

- 确认候选器件的实际角色。
- 删除误判的锚点。
- 补充前缀规则未发现的关键器件。
- 标明允许参与布局、保持固定或忽略的器件。

建议的器件处置字段：

```json
{
  "componentId": "...",
  "designator": "U1",
  "role": "ic",
  "disposition": "place"
}
```

`disposition` 可取：

- `place`：允许算法移动。
- `fixed`：保持当前位置，但参与障碍物和区域计算。
- `ignored`：安装孔、Logo 等无需归类和移动的对象；仍可按需要参与几何检查。

## 7. 阶段 A：功能区域归类

### 7.1 分配优先级

器件归类按以下优先级执行：

1. 明确的人工配置。
2. 原理图页归属。
3. 与锚点共享网络的得分。
4. 无法确定时进入 `unassigned`，不得静默丢弃。

机械器件、定位点、测试点、Logo 等应通过 `fixed` 或 `ignored` 明确处置，不应因为不属于功能锚点而永久阻塞门禁。

### 7.2 网络得分

器件 `component` 对锚点 `anchor` 的得分定义为：

```text
score(component, anchor)
  = Σ [1 / usage_count(net)]
```

求和范围是器件与锚点共享的非 GND 网络。一个网络的使用器件越多，其区分度越低。例如使用数为 2 的共享网络贡献 `0.5`。

GND、AGND 等全局地网络不参与归类得分。

### 7.3 锁定器件

锁定器件属于结构化输入：

- 可以参与区域归属和报告。
- 始终作为固定障碍物参与碰撞检测。
- 永远不得出现在最终变更列表中。
- 若锚点本身被锁定，则区域宏观位置和锚点旋转固定，只允许在其周围安排可移动成员。

碰撞检测必须按器件 ID 排除“与自身碰撞”，同时保留区域成员与锁定锚点本体之间的真实间距检查。

### 7.4 区域语义参数

程序生成 `region-params.template.json`，由 AI 或人工补充：

```json
{
  "U1": {
    "type": "digital",
    "farFrom": [
      { "anchor": "U5", "minDistanceMil": 800 }
    ],
    "edgeConstraint": null
  },
  "J1": {
    "type": "connector",
    "farFrom": [],
    "edgeConstraint": {
      "allowedEdges": ["left", "right"],
      "preferredEdge": "right",
      "requiredRotation": 90,
      "allowedOverhangMil": 50,
      "edgeClearanceMil": 50
    }
  }
}
```

约束含义：

- `farFrom` 使用两个区域包围盒之间的边到边距离。
- `requiredRotation` 是硬约束；缺失时允许使用不可靠的朝向启发式，但必须在报告中标记。
- `allowedOverhangMil` 只允许器件跨越最终选定的目标外板边，不能用于穿过其他板边或内部孔洞。
- `edgeClearanceMil` 表示器件与目标边的期望退让距离。

## 8. 板框与几何模型

### 8.1 闭环构造

板框图元按端点容差分桶并连接为闭环。圆弧在参与闭环和多边形运算前离散为线段。

对于圆弧半径 `R` 和最大弦高误差 `ε`，最大分段角为：

```text
theta_max = 2 * acos(clamp(1 - ε / R, -1, 1))
segment_count = ceil(abs(total_angle) / theta_max)
```

实现必须处理：

- `R <= 0`：图元非法，报告错误。
- `ε <= 0`：配置非法。
- `ε >= R`：进行安全钳制，且至少生成一个分段。
- 起点、终点、圆心和顺逆时针方向与 EasyEDA 图元定义一致。

默认最大弦高误差为 `2mil`。

### 8.2 外框和孔洞分类

不能简单地把“最大闭环以外的所有闭环”都认定为孔洞。轮廓应通过点包含关系建立层级：

- 包含深度为偶数的闭环表示实体外边界。
- 包含深度为奇数的闭环表示孔洞。

首版只接受一个深度为 0 的外部闭环，以及直接位于其内部的孔洞。出现以下情况时停止布局并报告：

- 多个互不包含的外部闭环。
- 孔中实体岛等更深层嵌套。
- 自交轮廓。
- 未闭合轮廓。
- 孔洞超出外框。

标准输出结构为：

```json
{
  "outer": [[0, 0], [1000, 0], [1000, 500], [0, 500]],
  "holes": [
    [[100, 100], [200, 100], [200, 200], [100, 200]]
  ]
}
```

### 8.3 板内判定

普通器件必须位于 `outer` 内部且不与任何 `hole` 相交。首版可采样器件包围盒四角和四条边中点，但报告中必须注明这是近似判定。

连接器的允许外伸只在指定目标外板边生效；其他外板边和内部孔洞仍按零外伸检查。

### 8.4 器件包围盒

若输入提供封装局部 courtyard 或封装图元，应从局部几何在新角度下重新计算轴对齐包围盒。

若输入只有当前角度下的轴对齐包围盒，可将其四角反旋转到近似局部坐标后再旋转到目标角度。该方法是保守近似，并非任意封装的精确包围盒；因此：

- 允许误报碰撞，不允许漏掉已发现的碰撞。
- `report.json` 应标注 `bboxMode: "conservative-aabb"`。
- 后续可通过 courtyard/封装图元升级为 `bboxMode: "footprint-geometry"`。

### 8.5 双面器件

碰撞检测应按顶层和底层分别建立障碍物集合。跨面的机械干涉只有在具有高度或专门 keepout 信息时才判断。

若首版未实现分面逻辑，必须拒绝含有可移动底层器件的输入，并报告仅支持单面布局。

## 9. 阶段 C：区域内布局与宏观布局

### 9.1 近引脚器件

匹配去耦规则的二焊盘器件必须满足：

- 一个焊盘网络与锚点的具体电源引脚网络相同。
- 另一个焊盘属于地网络。
- 放置目标是该具体锚点引脚，而不是任意共享网络。
- 优先让电源焊盘朝向目标引脚。

无法识别目标引脚时不得假装满足 near-pin 规则，应写入 `unsatisfiedConstraints`。

### 9.2 区域刚体变换

区域宏观移动和旋转使用同一个刚体变换 `(theta, dx, dy)`。设锚点变换前的位置和角度为 `anchor_pos_old`、`anchor_rot_old`：

```text
local = R(-anchor_rot_old) * (pos_old - anchor_pos_old)
pos_new = anchor_pos_new + R(anchor_rot_old + theta) * local
rotation_new = (rotation_old + theta) mod 360
```

焊盘位置不得只做平移。应先恢复到器件局部坐标，再使用器件的新坐标和新旋转计算：

```text
pad_local = R(-rotation_old) * (pad_abs_old - component_pos_old)
pad_abs_new = pos_new + R(rotation_new) * pad_local
```

锚点锁定时跳过区域宏观变换，只执行围绕固定锚点的区域内布局。

### 9.3 碰撞与重试

候选放置按以下顺序检查：

1. 所在面和模式是否受支持。
2. 板框及孔洞包含关系。
3. 禁布区。
4. 锁定器件和已放置器件的间距膨胀包围盒。
5. 边缘与外伸约束。
6. 区域间 `farFrom` 约束。

失败时尝试下一个确定性候选槽位。达到重试上限后，将器件加入 `unplaced` 或相应约束失败列表，不得强行放置。

连接器或天线 keepout 应来自显式配置或真实区域图元。天线可使用默认净空规则；连接器不得无条件套用大圆形净空区，以免排斥其必要的 ESD、匹配或支撑器件。

### 9.4 宏观区域布局

宏观布局按以下优先级执行：

1. 保留锁定锚点区域。
2. 放置具有硬性边缘约束的连接器、天线等区域。
3. 放置其他区域。
4. 检查 `farFrom`，执行有界交换或位置修复。
5. 无法满足时写入报告并让门禁失败。

算法必须是确定性的：相同输入和配置应生成相同输出。

## 10. 线长估算与回归判断

每个参与评估的网络使用焊盘点集最小生成树长度作为估算线长。以下网络排除：

- `GND`、`AGND`，不区分大小写。
- 已存在铺铜记录的网络。
- 使用器件数超过配置阈值的全局网络。

默认退化阈值为 5%：

```text
wirelengthRegression = after > before * 1.05
```

边界规则：

- 若 `before == 0` 且 `after == 0`，视为无退化。
- 若 `before == 0` 且 `after > 0`，不能计算百分比，应直接标记为退化并报告绝对增量。
- 报告除总量外，还应列出退化最大的若干网络，便于定位问题。

## 11. 输出文件

### 11.1 `changes.json`

算法生成的候选结果，仅供检查，不允许直接用于 MCP 写操作。

每条变更应同时保存目标状态和源状态：

```json
{
  "componentId": "...",
  "before": {
    "x": 100,
    "y": 200,
    "rotation": 0,
    "locked": false,
    "side": "top"
  },
  "after": {
    "x": 300,
    "y": 400,
    "rotation": 90
  }
}
```

### 11.2 `report.json`

至少包含：

- `outsideBoard`
- `overlaps`
- `unplaced`
- `unsatisfiedConstraints`
- `unassigned`
- `unsupportedGeometry`
- `estimatedWireLengthBefore`
- `estimatedWireLengthAfter`
- `wirelengthRegression`
- `bboxMode`
- 被排除网络和排除原因
- 锁定、固定、忽略和实际移动的器件数量

`unassigned` 中已经明确标记为 `fixed` 或 `ignored` 的对象不应导致门禁失败；未处置的普通电气器件仍应导致失败。

### 11.3 `validated-changes.json`

只有门禁全部通过时才生成：

```json

  "sourceComponentCount": 91,
  "changeCount": 36,
  "changes": [
    {
      "componentId": "...",
      "before": {
        "x": 100,
        "y": 200,
        "rotation": 0,

      },
```

## 12. 安全门禁与实际应用

`tools/pcb-layout/apply_gate.py` 是实际安全边界，不是命名约定。

只有以下条件全部满足时，才写出 `validated-changes.json`：

- 无板外器件。
- 无碰撞。
- 无未放置器件。
- 无未满足硬约束。
- 无未处置的普通器件。
- 无不支持的板框或几何结构。
- 无线长退化。
- 变更中不包含锁定或固定器件。

门禁失败时：

- 不生成验证文件。
- 删除同一输出目录中上次运行遗留的 `validated-changes.json`。
- 明确打印每项失败原因。

### 12.1 应用前实时校验

真正调用 EasyEDA MCP 前必须重新获取 `pcb_inspect` 快照，并逐条核对：

- PCB UUID 与验证文件一致。
- 每个 `componentId` 仍存在。
- 器件仍未锁定。
- 当前 `x`、`y`、`rotation`、`locked` 和 `side` 与 `before` 一致，数值比较使用明确容差。
- 目标层面和当前 PCB 仍满足首版支持条件。

任意一项不一致都应中止整批应用，重新生成布局结果。不得用绝对目标坐标覆盖规划后发生的人工移动。

### 12.2 MCP 应用规则

- 仅 `validated-changes.json` 可用于构造 `pcb_transform_components` 调用。
- `changes.json` 永远不视为可直接应用文件。
- 应尽量一次性提交同一批变更，并保留 MCP 返回结果。
- 应用后重新读取 PCB，核对实际坐标、旋转角度和锁定状态。
- 应用后的 DRC、网络连通性与机械检查仍需单独执行。

## 14. Value 归一化

Value 原始值按以下顺序读取：

```python
value = component.get("value") or component.get("otherProperty", {}).get("Value")
```

规则匹配前执行：

- 转小写。
- 合并空白。
- 统一 `u`、`µ`、`μ` 等微量前缀。
- 识别常见 SI 前缀并换算为隐含基本单位 F、H、Ω。
- 数值比较使用小的相对误差。

因此 `100nF`、`0.1uF` 和 `0.1µF` 应视为相等。`104` 等 EIA 简写首版保留原值并报告未解析，不做猜测。

## 15. 测试要求

使用 Python `unittest`，至少覆盖：

1. 小型网络上的 `1 / usage_count` 得分计算。
2. 非正交角度的区域刚体变换，包括器件坐标、旋转和焊盘坐标。
3. 保守 AABB 模式不会把近似结果宣称为精确几何。
4. 单一外框加孔洞，位于孔内的候选放置被拒绝。
5. 多外部闭环和嵌套实体岛被明确拒绝。
6. 非法圆弧、极小半径和 `ε >= R` 的边界处理。
7. 锁定器件作为障碍物且不会进入变更列表。
8. 自身 ID 不会造成自碰撞。
9. 连接器只在指定板边允许外伸，穿过其他边或孔洞仍被拒绝。
10. 顶层/底层碰撞策略或单面模式拒绝逻辑。
11. `fixed`、`ignored` 与真正未归类器件的门禁差异。
12. `before == 0` 的线长回归边界。
13. 强制制造线长退化时，门禁不生成验证文件并删除旧文件。
14. 应用前源坐标或旋转发生变化时，整批应用被拒绝。
15. 相同输入重复运行得到字节级一致的核心布局结果（时间戳除外）。

## 16. 验收标准

在真实 `pcb_inspect` 快照上完成端到端 dry run，并满足：

- 所有可移动电气器件都有明确区域归属。
- 固定和忽略对象有可追踪的处置记录。
- 锁定器件未被移动。
- 报告中无板外、碰撞、未放置和硬约束失败。
- 估算线长未超过允许退化阈值。
- 只有门禁通过后才出现 `validated-changes.json`。
- 修改任一器件源坐标后，旧验证文件不能通过实时校验。
- 使用验证文件调用 MCP 后，重新读取到的实际位置与目标一致。

## 17. 推荐实施顺序

1. 实现 `model.py` 和规范化快照哈希。
2. 实现 `geometry.py`，优先完成板框、圆弧、碰撞和刚体变换单元测试。
3. 实现 `anchors.py` 与人工确认文件格式。
4. 实现 `regions.py` 和区域参数模板。
5. 实现 `place.py` 的区域内布局，再实现宏观布局。
6. 实现线长评估和 `report.json`。
7. 实现 `apply_gate.py` 与应用前实时状态校验。
8. 使用真实快照 dry run；检查报告后再进入 MCP 板上测试。

这套顺序优先验证最容易造成静默错误的几何与安全边界，再逐步加入布局启发式。
